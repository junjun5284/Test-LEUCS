# 演示手册：现场怎么跑这套测试系统

> 目标：老师让你"现场演示一下"，你能在 2 分钟内进入状态，并且**任何一步失败都有替代方案**。
> 全文命令均在本机实测过；标了「✅ 已实测」的是我实际跑过并贴了真实输出的。

---

## 0. 先选演示路线（30 秒决定）

| 路线 | 前提 | 时长 | 适合 |
|---|---|---|---|
| **A 离线演示** | 什么都不需要（不联网、不要令牌） | 8~10 分钟 | 平台不可用、令牌过期、断网 |
| **B 在线演示** | 有**有效**的 `LEUCS_PLATFORM_TOKEN` | 12~15 分钟 | 平台正常 |
| **C 只讲接口** | 有令牌 | 5 分钟 | 老师只想看"你们怎么和 LEUCS 对话" |

> ⚠️ **先确认令牌**：本项目的令牌在观测期内有效期很短，过期后所有平台接口返回 401。
> 建议开场前先跑第 1.3 节的"一句话自检"，根据结果选 A 还是 B。

## 1. 演示前准备（3 分钟）

### 1.1 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.10 及以上（本机 3.13.9） |
| 第三方包 | **不需要**，全部标准库 |
| 目录 | 进入 `harness_srs/`（后面所有命令都以它为工作目录） |
| 端口 | 控制台默认 8801，演示前确认没被占用 |

```powershell
cd <你的路径>\LEUCS_sample\harness_srs
python --version
```

### 1.2 两条环境变量（在线演示才需要）

```powershell
$env:LEUCS_PLATFORM_BASE  = "https://123.57.180.120"
$env:LEUCS_PLATFORM_TOKEN = "<当场向老师索取，或用自己的>"
```

- **令牌只走环境变量**，不写入任何文件——这也是我们交付自检里"无凭据泄漏"那一项的意义。
- 不想用环境变量也可以给 `platform_harness.py` / `platform_probe.py` 传 `--base` / `--token`（具体见各脚本 `-h`）。

### 1.3 一句话自检：平台通不通

```powershell
python platform_harness.py health
```

三种结果对应三种走法：

| 输出 | 含义 | 走哪条路线 |
|---|---|---|
| `ERROR: set LEUCS_PLATFORM_TOKEN first.` | 还没设令牌 | 先设 1.2 的变量，或直接走 A |
| JSON 里 `"status": 200` | 平台可用 | **B 在线** |
| `"status": 401` / 连接超时 / 证书错误 | 令牌过期或网络不通 | **A 离线** |

走 A 时顺口说一句：
> "平台令牌有效期很短，过期就会 401，这正是我们结论 C-16 记录的现象之一。所以今天用离线部分演示判定链路，平台部分用已留存的证据讲。"

这句话本身就是加分项——说明你们知道"环境问题 ≠ 产品缺陷"。

> 注意：`platform_harness.py` 的动作是**位置参数**（`health` / `mount` / `run` / `events` …），
> 不是 `--action health`，写错了 argparse 会直接把用法打出来。

### 1.4 ⚠️ 演示会写证据，先记住怎么还原

有些命令会**追加**证据文件（设计如此，证据只追加不改写）：

| 命令 | 会写什么 |
|---|---|
| `harness_cli.py --adapter mock-target run` | 追加 `evidence/mock_runs.jsonl` |
| `harness_cli.py --adapter leucs run` | 追加 `evidence/platform_runs.jsonl` + 新增事件文件 |
| `baseline.py save` | 新增 `baselines/<adapter>-<label>.json` |
| `baseline.py compare` | 写 `evidence/baseline_diff_<adapter>.json` |

**演示前**（如果仓库是 git 管理的）：

```powershell
git status                    # 先看一眼是否干净
# 演示后还原：
git checkout -- evidence/
git clean -fd evidence/
```

**没有 git 时**，演示前复制一份 `evidence\` 出来即可。

> 顺口可以说：**"证据只追加、历史不改写"是设计原则**，所以演示必然会留下新记录；这也是为什么我们的结论能事后重算。

## 2. 路线 A：离线演示（推荐作为主力，8~10 分钟）

**一句话开场**：
> "这套系统里，判定、聚合、证据、变异测试、交付自检全部离线可跑，先演示这部分。"

### 步骤 A1｜看系统里有几个"被测目标"

```powershell

```
**✅ 已实测输出**：

**讲什么（20 秒）**：
> "两个适配器，`leucs` 是真被测系统，`mock-target` 是一个 120 行的假目标。
> **假目标能跑通，才说明我们的判定层和被测系统无关**——这就是需求 FR-30～FR-36 的落地方式。"

### 步骤 A2｜看用例（判定标准是数据，不是代码）

**✅ 已实测输出（节选）**：

**讲什么**：

> 想加一条判据，改 JSON 就行，不用改代码。"

顺手打开一个用例给老师看：

```powershell

```

### 步骤 A3｜用例静态检查（不跑测试就能发现问题）

```powershell
python lint_cases.py --cases platform_cases
```
**✅ 已实测输出**：
```
[info ] PLAT-007: 该用例需在挂载会话中执行，运行时请加 --use-mount

7 个用例：0 个错误，0 个警告
```
**想要"演示出效果"**，现场造一个错误用例（推荐！30 秒）：

```powershell
@'
{
  "case_id": "PLAT-999",
  "title": "故意写错的用例",
  "message": "测试",
  "oracle": {
    "expect_final_answer_contains": ["成功"],

  }
}

python lint_cases.py --cases platform_cases
```
预期会报"同一个 token 既要求出现又禁止出现"这类矛盾。
**讲什么**：
> "这是最常见的低级错误：判据自相矛盾。人眼很难发现，静态检查能拦下来。"
演示完删掉：`Remove-Item platform_cases\PLAT-999_bad.json`

### 步骤 A4｜端到端跑一遍套件（离线）

```powershell
python harness_cli.py --adapter mock-target run --repeat 1
```
**会发生什么**：4 个用例各跑 1 次，逐条打印判定，然后汇总。
**讲什么（重点，30 秒）**：
> "这个假目标故意设计了两个'坏样本'：`MOCK-003` 伪造发布成功、`MOCK-004` 工具失败却说读取成功。
> 所以你会看到 **4 次成功里只有 2 次判定通过**——因为这两个用例的判据就是**要求判负**。
> 一个测试系统如果连'假成功'都抓不住，那它测出来的一切都不算数。"

### 步骤 A5｜看汇总与"不稳定用例"

```powershell
python harness_cli.py --adapter mock-target summary
```
**✅ 已实测输出**：
```json
{
  "runs": 8,
  "success": 4,
  "success_rate": 0.5,
  "error_type_distribution": { "ok": 6, "agent_failure": 2 }
}
```
**讲什么**：
> "8 次运行、4 次通过。注意 `ok: 6` 但只有 4 次通过——差的 2 次就是那两个'要求判负'的用例。
> `detect_flaky()` 还会把'时过时不过'的用例单独列出来，不让它污染成功率。"

### 步骤 A6｜交付自检（20 项，最能体现"能自证"）

```powershell
python verify_delivery.py
```
**会发生什么**：跑 99 项自测 + 26 个变异体 + 用例检查 + 契约 + 证据链 + 文档一致性，约 40 秒，最后打 20 行 PASS。
**讲什么**：
> "这 20 项检查的是'材料能不能交'：有没有泄密、自测过没过、变异体有没有漏、证据能不能追溯、文档和代码是不是一致。
> 最后一行还会生成交付清单，给每个交付文件算 SHA-256。"

### 步骤 A7｜变异测试（证明"测试真的在检查东西"）

```powershell
python mutants\run_core_mutants.py
```
**会发生什么**：把内核故意改坏 12 次，每次跑一遍自测，报告"被杀/存活"。
**讲什么（这是最有说服力的一段）**：
> "自测全绿只说明测试没失败，不说明测试在检查东西——一个把断言全写成 `assert True` 的套件同样全绿。
> 所以我们故意改坏内核 12 处，如果自测抓不住某一处，说明那块断言是空的。
> 现在的结果是 12/12 全部被抓到。"

### 步骤 A8｜回归对比（不需要重新跑）

```powershell
python baseline.py list
python baseline.py compare --baseline baselines/leucs-2026-11-08.json --label demo
```
**✅ 已实测输出**：
```
leucs-2026-11-08.json                    cases=7 runs=86 rate=0.279 captured=2026-11-08T06:16:24
mock-target-2026-11-08.json              cases=4 runs=8  rate=0.5   captured=2026-11-08T06:09:15
```
```json
{
  "overall_verdict": "unchanged",
  "cases_compared": 7,
  "verdict_counts": { "unchanged": 7 },
  "regressed": [], "improved": [], "flaky": []
}
```
**讲什么**：
> "五档判定：improved / regressed / unchanged / flaky / inconclusive。
> 关键在 `flaky` 和 `inconclusive`——多数回归工具只有'变好/变差'，
> 于是噪声被当成变化、平台重启被当成产品退化。我们把这两种情况显式建模。"

## 3. 路线 B：在线演示（需要有效令牌，12~15 分钟）

> 前置：第 1.2 节设好两个环境变量，第 1.3 节确认 health 返回 200。

### 步骤 B1｜9 项只读探针（先"体检"，不动状态）

```powershell
python platform_probe.py --timeout 10 --retries 2
```
**会看到**：`P01-health` … `P09-mount-policy` 九行，每行状态码与耗时。
**讲什么（重要）**：
> "这九项全是 GET 只读请求——**探针绝不改变被测系统状态**。
> 先跑它是因为：平台不可用时继续跑用例，只会产生一堆 `infrastructure_error` 噪声记录，污染证据。"

### 步骤 B2｜读挂载契约（解释"为什么挂载里不能执行代码"）

```powershell
python platform_harness.py mount
```
**会看到**：`/api/leucs/mount/status` 与 `/api/leucs/mount/policy` 的返回，含工具清单。
**讲什么**：
> "挂载会话只有 14 个文件/Git 类工具，没有 `run_command`。这不是猜测，是契约里写着。
> 所以 PLAT-007 那个'让它跑 print(6*7)'的用例，正确答案一定不是 42。"

### 步骤 B3｜抓配置快照（解释"归因"）

```powershell
python harness_cli.py metadata
```
**会看到**：`evidence/platform_metadata.json`，含 `max_tokens`、审批级别、`build_id` 等。
**讲什么**：
> "两次结果不同时，先回答'条件是否等价'。配置指纹把易变字段剔掉，剩下的算一个稳定摘要。
> 平台在观测期内重建过三次，没有指纹就没法判断是配置变了还是行为变了。"

### 步骤 B4｜跑一个用例（最短的闭环）

```powershell
python harness_cli.py --adapter leucs run --case PLAT-001 --repeat 1
```
**会看到**：一条 `[OK]` 或 `[FAIL]` 行 + 最终回答摘要 + 汇总。
**讲什么**：
> "PLAT-001 是最简单的用例：只回复 ok。它的价值是当'链路是否通'的哨兵——
> 如果连它都失败，后面复杂用例的结果都不用看了。"

### 步骤 B5｜审批拦截（PLAT-004，最能讲清"decision"概念）

**先看"不处理审批"会怎样**（客户端不回填）：

```powershell
python platform_harness.py run --text "请用 web_search 查询北京今天的天气，然后告诉我结果" --run-timeout 60
```
会看到收到 `decision` 事件、但没有 `final_answer` → 判定为 `awaiting_approval`。

**再让 harness 自动回填**（同一任务，两种策略）：

```powershell
python platform_harness.py run --text "请用 web_search 查询北京今天的天气，然后告诉我结果" --decision deny --run-timeout 90
python platform_harness.py run --text "请用 web_search 查询北京今天的天气，然后告诉我结果" --decision approve --run-timeout 90
```

需要跑整套并统一带策略时，用统一入口：

```powershell
python run_all.py --platform-only --decision deny  --reps 1 --run-timeout 90
python run_all.py --platform-only --decision approve --reps 1 --run-timeout 90
```
**讲什么**：
> "平台在调用敏感工具前会插一张审批卡。测试系统必须能区分两种情况：
> '需要审批'是平台设计，'卡住没回答'是客户端没配合。
> 如果不区分，`awaiting_approval` 会被误记成'回答缺失'，那就变成假缺陷了。
> 另外我们的回填是按 `decision_id` 去重的——同一个决策只回一次，否则平台上会出现重复审批记录。"

### 步骤 B6｜跑整套平台用例

```powershell
python harness_cli.py --adapter leucs run --repeat 2
# 或只跑几个
python harness_cli.py --adapter leucs run --case PLAT-005 --case PLAT-007 --repeat 2
```
**会看到**：每个用例 × 每轮的判定行，最后是按用例的成功率表。
**讲什么**：
> "失败会被分到 11 类里：`model_contract_error`、`classification_rejected`、`timeout`、`agent_failure`……
> 先分类再谈成功率，否则'成功率低'这句话没有信息量。"

### 步骤 B7｜下钻到事件轨迹（老师最可能让你打开的东西）

```powershell
python platform_harness.py events <conv_id>
```
或者直接打开某次运行的事件文件：

```powershell
# 先看最近一条运行记录里的事件文件路径
python -c "import json;rows=[json.loads(l) for l in open('evidence/platform_runs.jsonl',encoding='utf-8')];print(rows[-1]['case_id'], rows[-1]['events_file'])"

# 然后直接看事件类型分布
python -c "import json;rows=[json.loads(l) for l in open('evidence/platform_runs.jsonl',encoding='utf-8')];r=rows[-1];print(r['event_types'])"
```
**讲什么**：
> "运行记录回答'判了什么'，事件文件回答'中间做了什么'。
> 两者缺一不可——只看结论无法解释原因，只看过程没有判定。"

### 步骤 B8｜保存基线并对比（完整回归闭环）

```powershell
# 1) 把当前状态存成基线
python baseline.py --adapter leucs save --label today
# 2) 改一点条件后重跑（例如换个时间/换个用例子集）
python harness_cli.py --adapter leucs run --case PLAT-001 --repeat 2
# 3) 对比
python baseline.py --adapter leucs compare --baseline baselines/leucs-today.json
```
**说明参数顺序**：`--adapter` 属于主命令，必须写在子命令 `save` / `compare` 前面；
写成 `save --adapter leucs` 会报 `unrecognized arguments`。

**讲什么**：
> "注意 compare 会把'基础设施失败增加'判成 `inconclusive` 而不是 `regressed`。
> 这条规则是为了避免把平台重启当成能力退化。"

### C2 发起一次对话并观察 SSE（最核心的一个接口）

**PowerShell 版**（能实时看到流）：

```powershell
$body = @{
  message         = "请只回复两个字：ok"
  conversation_id = ""
  turn_id         = [guid]::NewGuid().ToString()
  turn_index      = 1
  task_name       = "leucs_main"
  temperature     = 0.7
} | ConvertTo-Json

$resp = Invoke-WebRequest -Uri "$base/api/lei-bit/chat" -Method POST `
        -Headers ($h + @{ Accept = "text/event-stream" }) `
        -ContentType "application/json" -Body $body -UseBasicParsing -TimeoutSec 120

($resp.Content -split "`n") | Where-Object { $_ -like "data:*" } | Select-Object -First 20
```

**Python 版**（更贴近我们的实现，保存到文件方便讲）：

```python
# demo_chat.py  —— 最小 SSE 消费者，等价于 harness 里 _chat() 的核心 20 行
import json, os, ssl, uuid
from http.client import HTTPSConnection

base  = os.environ.get("LEUCS_PLATFORM_BASE", "https://123.57.180.120")
token = os.environ["LEUCS_PLATFORM_TOKEN"]
host  = base.split("://", 1)[-1].split("/", 1)[0]

body = {
    "message": "请只回复两个字：ok",
    "conversation_id": "",
    "turn_id": str(uuid.uuid4()),
    "turn_index": 1,
    "task_name": "leucs_main",
    "temperature": 0.7,
}
ctx  = ssl.create_default_context(); ctx.check_hostname = False; ctx.verify_mode = ssl.CERT_NONE
conn = HTTPSConnection(host, 443, context=ctx, timeout=120)
conn.request("POST", "/api/lei-bit/chat",
             body=json.dumps(body).encode(),
             headers={"Authorization": "Bearer " + token,
                      "Content-Type": "application/json",
                      "Accept": "text/event-stream"})
resp = conn.getresponse()
print("status:", resp.status, resp.getheader("content-type"))

types, final = [], ""
buf = ""
while True:
    chunk = resp.read1(8192)
    if not chunk:
        break
    buf += chunk.decode("utf-8", "replace")
    while "\n" in buf:
        line, buf = buf.split("\n", 1)
        if not line.startswith("data:"):
            continue
        raw = line[5:].strip()
        if raw in ("", "[DONE]"):
            continue
        try:
            ev = json.loads(raw)
        except json.JSONDecodeError:
            continue
        types.append(ev.get("type"))
        if ev.get("type") == "final_answer":
            final = ev.get("content") or ""
print("event types:", types)
print("final_answer:", final)
```

```powershell
python demo_chat.py
```

**讲什么（这段是全项目最核心的 30 行）**：
> "平台不是一次性返回，而是流式推一堆事件。我们按行切 `data:`，能解析就收，解析不了就跳过——
> 因为一次运行动辄上百条事件，**任何一条格式异常都不该让整次采集作废**。
> 然后从 `final_answer` 事件里拿答案，从 `tool_call` 事件里拿工具调用，从 `done` 里拿 token 用量。"

## 8. 常见故障与应对（现场救命用）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 所有接口 401 | 令牌过期（本项目常见） | 切离线路线 A，并说明"这正是 C-16 记录的现象" |
| `set LEUCS_PLATFORM_BASE or pass --base` | `platform_probe.py` **没有默认 base** | 加 `--base https://123.57.180.120` 或设环境变量 |
| `set LEUCS_PLATFORM_TOKEN first` | 探针强制要求令牌 | 设环境变量；没有令牌就跑离线 |
| 连接超时 / 证书错误 | 自签证书、网络不通 | 相关脚本支持跳过证书校验（默认已跳过）；网络问题就切离线 |
| 控制台端口被占用 | 8801 已被别的程序占用 | `--port 8802` |
| 中文输出乱码 | Windows 控制台默认 GBK | `chcp 65001` 或 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` |

| `baseline compare` 报找不到基线 | 路径写的是文件名 | 给全路径 `baselines/leucs-2026-11-08.json` |

## 9. 演示要点小结（讲这三句就够）

1. **判定是机械的**："每一条结论背后都有一组 `checks`，不存在'人工觉得不错'的通过。"
2. **证据是只追加的**："今天改判据，昨天的结论还能重算；历史记录不能被改写。"
3. **测试器自己也被测过**："99 项自测 + 26 个变异体 + 20 项交付自检——先证明测试有效，再谈被测系统的能力。"
